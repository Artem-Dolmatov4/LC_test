# MLAW RAG — поиск по правовым актам города Москвы

RAG-пайплайн поверх полнотекстовой выгрузки правовых актов Москвы:
инвентаризация → нарезка → индекс → поиск → оценка → ответ с цитатами.

Уровень исполнения **L2**: point-in-time поиск по дате (правильная **редакция**
акта, а не просто акт), дедуп выдачи по акту, переранжирование и ответ,
каждая ссылка в котором проверяется программно — резолвится в реальный
диапазон текста и дословно сверяется с ним.

стадии ответа и то, что юридическая корректность ответа не измеряется вовсе.

## Результат

Инвентаризация — сплошной проход по **всему** банку (266 657 записей).
Индекс и оценка — срез из **800 актов со всеми их редакциями**: 1 039 документов,
119 млн знаков, 64 031 фрагмент. Корзина — 136 запросов пяти типов,
dev 54 / test 82; все настройки подбирались на dev, числа ниже — один прогон
на замороженном test.

| | |
|---|---|
| recall@10 по акту, полный конвейер | **0.988** (MRR 0.934) |
| то же, гибрид без реранка | 0.939 (MRR 0.731) |
| контроли: подмена эталона / случайный ретривер | 0.024 / 0.012 |
| ссылки в ответах резолвятся в текст | 96.6 % |
| цитаты дословно совпадают с текстом | 93.1 % |

Метрика считается на трёх уровнях — `act_id`, `doc_id` редакции и фрагмент;
уровень фрагмента самый строгий и посчитан по 24 запросам из 82.

## Данные

Ожидается `MLAW_dataset.tar.zst` в корне репозитория (**в git не хранится**,
1.1 ГБ сжатого): 28 шардов JSONL по 9 523–9 524 записи, 28 бинарных сайдкаров
`.oix`, `mlaw_manifest.json` и `mlaw_stats.json`. Всего 266 657 записей,
16.94 ГБ в распакованном виде.

Корпус читается **потоком прямо из архива** — распаковывать его на диск не нужно:
zstd отдаёт 3.4 ГБ/с, полный проход с разбором JSON занимает 40 секунд.

## Запуск

Нужен Python ≥ 3.12 (проверено на 3.14). Ключи API для этого шага не нужны.

```bash
make setup && make test
```

136 тестов проходят за ~2 секунды. Тесты, которым нужен настоящий архив,
пропускаются сами, если его нет на месте:

```bash
make test-slow
```

Весь пайплайн с нуля — инвентаризация → срез → нарезка → индекс → корзина →
оценка → абляция → ответы с цитатами. Нужен Docker (под Qdrant) и ключи
`VOYAGE_API_KEY` с `DEEPSEEK_API_KEY` в `.env` (шаблон — `.env.example`,
Makefile подхватывает файл сам):

```bash
make setup && make qdrant && make all
```

Отдельные шаги — `make inventory | slice | chunk | lexical | index | basket |
eval | ablation | answers`, полный список с описаниями выдаёт `make` без
аргументов.

**Прогон не бесплатный по времени:** только стадия эмбеддингов — 33 минуты
и 56.6 млн токенов Voyage (из 200 млн бесплатных на аккаунт). Стадия
детерминирована входом и защищена кэшем векторов, так что прерванный прогон
продолжается с места обрыва, а не начинается заново.

## Что в git, а что считается заново

В репозитории лежат **сдаваемые числа**: `reports/REPORT.md`, `reports/report.html`
и 13 JSON-замеров — от `inventory.json` до `answers_test.json`. Без них
утверждения отчёта нечем подтвердить, поэтому они трекаются.

Не лежат и восстанавливаются прогоном: `data/` (срез, чанки, векторы, индекс
BM25), `qdrant_storage/`, сам архив и `.env`.

Поэтому воспроизводимость проверяется как `rm -rf data/ && make all` —
каталог `reports/` сносить не нужно, `make all` перезапишет его сам.

## Воспроизводимость

Детерминизм проверен побайтово до стадии ответа: повторная сборка с тем же
зерном (`SEED=20260815`) даёт идентичные `slice.jsonl`, `slice.oix`,
`chunks.jsonl` и все файлы корзины — сверено по sha256. Поиск и оценка на
замороженном индексе тоже воспроизводятся.

Стадия ответа недетерминирована — это единственная такая стадия, и §6 отчёта
показывает разброс по трём прогонам вместо одного числа. Зато проверка цитат
воспроизводима отдельно от генерации: ответы и приведённые моделью выдержки
сохраняются целиком, и `--reverify` пересчитывает проверку по ним без единого
обращения к модели.

## Устройство

| Модуль | Назначение |
|---|---|
| `src/mlaw/oix.py` | чтение и запись сайдкара `.oix`, доступ по `doc_id`, проверка инвариантов |
| `src/mlaw/stream.py` | потоковое чтение корпуса из `.tar.zst` или из распакованной папки |
| `src/mlaw/inventory.py` | шаг 1 — сплошной проход по банку (266 657 записей за 40 с) |
| `src/mlaw/slice_build.py` | шаг 2 — срез по актам с полными цепочками редакций |
| `src/mlaw/chunk.py` | шаг 3 — трёхуровневая нарезка |
| `src/mlaw/index.py`, `src/mlaw/lexical.py` | шаг 4 — плотный индекс (Qdrant) и BM25 |
| `src/mlaw/embed.py` | клиенты эмбеддеров: Voyage, Ollama, DashScope |
| `src/mlaw/basket.py`, `src/mlaw/evaluate.py` | шаг 5 — корзина запросов и оценка с контролями |
| `src/mlaw/search.py`, `src/mlaw/citations.py`, `src/mlaw/answer.py` | шаг 6 — конвейер L2, резолв цитат и ответы |
| `src/mlaw/gate.py` | шаг 0.5 — замеры пропускной способности эмбеддеров |

Тяжёлый стек (`qdrant-client`, `bm25s`, `sentence-transformers`, клиенты
моделей) вынесен в extras `pipeline`: каркас и тесты инвариантов поднимаются
без него.

Модели: `voyage-context-4` (1024 измерения) — плотная нога, BM25 с русским
стеммингом — лексическая, слияние RRF, переранжирование `bge-reranker-v2-m3`,
ответ `deepseek-v4-pro`. Векторная база — Qdrant.

136 тестов, детерминизм сборки среза и нарезки проверен побайтово (sha256).
